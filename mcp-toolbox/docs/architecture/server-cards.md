# Server Cards And Progressive Discovery Metadata

## Status

Implemented for the W058/W059 baseline on 2026-09-19. Evidence note:
`docs/superpowers/specs/2026-09-19-w058-w059-mcp-alignment-evidence.md`.

## Context

The MCP Server Card Working Group standardizes `.well-known` metadata so a
server can be discovered and reasoned over without connecting to it. SDK
1.30.0 ships no card schema or helper, so this repository generates a
first-party card from a single source of truth.

Separately, MCP guidance recommends progressive discovery when tool
definitions become a large share of model context. The accepted decision in
`tool-exposure-context-economics.md` assigns progressive disclosure to the
**host/provider boundary**: servers keep publishing complete, stable
`tools/list` capabilities and do not simulate lazy loading with
connection-local catalogs.

## Decision

Every product ships `apps/<product>/.well-known/server-card.json`, generated by
`@agent-tools/protocol-baseline` from exactly two inputs:

1. the product's `package.json` (name, version, description), and
2. the product's compiled `tools/list`, captured over the real MCP stdio
   boundary.

The card carries the protocol version, transport, capabilities, a compact tool
index (names, descriptions, `readOnly`/`taskSupport` hints), and the measured
full-catalog and index byte counts. It never duplicates a hand-maintained tool
list.

Progressive discovery is therefore exposed as **host-facing metadata**: a host
can inject the compact index first and fetch full definitions with the
standard `tools/list` on demand. No server-side dynamic catalog is added,
consistent with `tool-exposure-context-economics.md`.

## Tooling

- Generate: `pnpm run cards:generate` (from `mcp-toolbox/`).
- Check drift: `pnpm run cards:check` (exit 1 on missing/stale cards).
- Enforced in `pnpm run verify` by `packages/protocol-baseline/src/cards.test.ts`,
  which validates every committed card against the schema and against the live
  compiled catalog.
- Measure the index-vs-catalog token delta: `pnpm run protocol:measure`.
- Run the conformance smoke: `pnpm run protocol:conformance`.

## Consequences

A tool added, renamed, or re-schematized changes the compiled catalog, so the
card drift test fails until `cards:generate` is re-run and the artifact
committed. The card schema is a first-party convention (the WG schema is not in
the SDK); when the WG ships an official schema, `cards.ts` is the single place
to migrate.
