## Summary

W073 — a **bounded recursive self-improvement loop** (the Karpathy-style propose → apply → test → evaluate → commit/discard cycle) that runs on top of Workflow's existing authority, evidence, and review machinery, plus the operator surfaces to trigger, monitor, and cancel it, plus the **W074 scheduled-task manager backend** and the **Sessions → Agents UI rename** with a new Schedules page.

- **The loop** (`src/integrations/self-improvement-loop.ts`): every candidate is routed through the canonical run lifecycle, so a commit happens only after the kernel reaches `VERIFIED` on fresh evidence (hub tests + reviewer when required). Safety invariants, each test-pinned: clean-baseline precheck (refuses a dirty tree or non-repo, so the destructive discard can only revert the loop's own changes); boundary-scoped cancel; iteration/rejection/budget caps; fail-closed rollback (a failed close or discard stops the loop); verified-but-uncommittable candidates are audited, never claimed as committed; realpath-keyed single-instance lock. The reviewer's run ask is the operator-authored objective, never the candidate's hypothesis.
- **Trigger / monitor / cancel**: hub-owned registry + `POST /rsi/start|status|cancel` + `workflow-rsi` CLI. `/rsi/start` and `/schedule/run-now` require the **verifier credential** (the credential that may finish runs), not the ordinary surface token; `requiresReview` defaults to true with explicit opt-out. `THREAT_MODEL.md` records the dated residuals (credential-scoped boundary, reviewer-injection, in-memory registry).
- **Scheduled-task manager (W074)**: `enabled` pause flag, `nextCronMatch` preview, `trigger()` run-now with double-fire/overlap guards, live `schedule-registry.ts` over the persisted table, `/schedule/*` routes, and `cli/hub.ts` composing an always-on scheduler + fail-closed loop registry.
- **Web UI**: the Sessions page is renamed **Agents** (truthful; avoids confusion with transcript history; `/sessions` kept as a command alias; `/api/sessions*` wire names unchanged and test-pinned). New **Schedules** nav slug projects the hub cron table (pause/resume, delete, next-run) and the loop registry (state, iterations, cancel) through the web service's hub proxy — the hub stays the single writer and the browser never holds a hub token; loop start and schedule run-now are deliberately CLI-only and the page says so.

Independent review: multiple fresh-context five-axis rounds, including an operator-directed adversarial reviewer with its own primary-source research (OpenRouter long-horizon + HITL cookbooks, Anthropic agent guidance, Anthropic RSI institute piece, METR) — two P0s and two P1s were found and fixed; final adversarial verdict **APPROVED** (recorded). Dated prior-art mapping and long-horizon gap ledger live in the plan doc.
