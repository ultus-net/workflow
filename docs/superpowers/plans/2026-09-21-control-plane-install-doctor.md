# Control-plane install: vendored fleet payload, doctor checks, plugin-free posture (W086)

Date: 2026-09-21 · Branch: `feat/control-plane-install-doctor` · Base: main @ 9471425

## Problem

The OpenCode agent fleet (`decompose` / `executor` / `reviewer` /
`retrospective`), its slash commands (`/decompose` `/retro` `/review-diff`
`/rsi-loop`), and the companion repo docs they reference
(`rsi-loop-playbook.md`, `task-decomposition.md`, `reading-list.md`,
`lessons.md`) existed only as a hand-maintained draft in the operator's
dotfiles repo, promoted into the installed config by manual copying — the
least auditable channel (the guard-policy findings, F2: the promotion step,
not the drafting step, is where review and audit disappear). Nothing
verified that the installed config actually carries the fleet, or that it
matched the draft.

## Decision (operator-directed, 2026-09-21)

1. **Vendor the whole fleet payload in-repo** (`assets/opencode-fleet/`):
   agents, commands, and the full companion docs folder (all of it — every
   file serves a purpose), copied verbatim from the dotfiles draft, with a
   committed sha256 manifest regenerated by
   `scripts/generate-fleet-manifest.mjs`. A focused drift guard test
   re-runs the generator's logic and fails when the manifest and the assets
   disagree — the manifest can never silently rot.
2. **`workflow install fleet [--force]`** (`src/cli/install.ts`) is the
   deployment path. The explicit command IS the ask-gate (tier T1):
   agents/commands install into the host config dir with refuse-to-clobber
   (a locally-modified install survives unless `--force`); the docs bundle
   is **install-if-missing only** — repo-owned living files (`lessons.md`
   is append-only per-repo memory) are never overwritten, force or not.
   Writes are atomic (temp + rename); nothing is deleted.
3. **`workflow doctor` gains two checks** (the doctor stays read-only and
   prints the sanctioned path both ways, per the operator's direction):
   - *fleet payload* — installed-and-matching vs the committed manifest;
     missing = fail, drift = warn; the fix line carries `workflow install
     fleet` AND the exact per-file `cp` commands for the do-it-by-hand path.
   - *guard enforcement posture* — the plugin-free aim stated honestly:
     hub-launched sessions carry the guard at launch
     (`createConfiguredAcpRuntime(..., guard)`); raw host launches are
     unguarded **by design (operator's choice)**; a host config that still
     registers the workflow-guard plugin is a warn, not an error, and the
     fix line routes through a recorded parity probe — no parity claim is
     made before the probe register carries one.
4. **The host config document (`opencode.jsonc`) is never written** by the
   installer or the doctor. It is the permission surface (tier T0 once
   deployed); the doctor verifies and prints fragments, and every change to
   it stays an operator edit in the dotfiles draft (tier T2) promoted by the
   operator. The RSI loop must never be pointed at it (ruler integrity).
5. **The dotfiles repo stops carrying the fleet** once this lands (one
   source per artifact: the Workflow repo owns the vendored payload;
   dotfiles keeps `opencode.jsonc` and personal config). Cleanup of the
   dotfiles side is the operator's follow-up.

## Honest claims and residuals

- The vendored docs are copied **verbatim** from the operator's authored
  draft, including their dotfiles-anchored sections ("Anchoring to this
  dotfiles repo"); adapting that framing in target repos is the operator's
  editorial call, never a silent mutation by the installer.
- `checkGuardPosture` reports the recorded state only. The raw-launch
  parity probe (hub-guarded session vs plugin session) is **not yet
  recorded**; until it is, the posture check claims nothing beyond
  "hub-launched sessions are guarded at launch".
- The `workflow` launcher's install dispatch is covered by the focused
  suite at the module level (`parseInstallArgs` + `installFleet`); the
  two-line dispatch in `src/cli/workflow.ts` is typecheck-verified, same
  discipline as the other launcher verbs.
- Vendored-asset completeness at commit time is pinned by the drift-guard
  test (12+ entries); it fails loudly if the payload is partial.
