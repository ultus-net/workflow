### W174 (stretch) - The ⌘K command palette: the shell's pages join the session's slash commands in the ONE existing palette (2026-09-30)

**Source:** GitHub issue #345 (closed; this PR refs it); the hub-dashboard redesign spec's stretch section (`docs/superpowers/specs/2026-09-29-hub-dashboard-redesign-design.md:226`: "Stretch — ⌘K command palette ... only if phases 1–4 leave appetite; not committed"). The spec's Option C listed the ⌘K palette as a stretch goal, not a commitment.

**GO verdict and what landed:** the integration was judged clean and shipped — `CommandPalette` is a pure component and its command list is built inside `AppShell`, which already owns `setView` and the `commandView` import, so the pages join the existing list rather than a second palette being built.

- **The ⌘K chord** (`src/ui/webapp/app.tsx`): `isPaletteChord` — Ctrl/Cmd+P (the existing OpenCode affordance, kept) and Ctrl/Cmd+K (the editor-standard chord) both toggle the palette through the AppShell keydown effect's existing branch; Alt never rides, a bare `k` stays composer text. Wired beside (not into) the existing `/` focus and Escape handlers; the palette's own Esc/Enter manners are untouched.
- **The shell's pages in the one list** (`src/ui/webapp/app.tsx`): `palettePageEntries(setView)` builds one `Go to <page>` entry per `APP_VIEWS` route in rail order, each dispatching **through `commandView`** — the same slug mapping the composer's slash dispatch routes — so palette navigation and slash navigation share one page vocabulary. The `PaletteCommand` group union gains `"page"` (`GROUP_LABEL`: "Pages"); the list reads Commands, Pages, Sessions, Slash commands with the existing as-you-type filter applying across all of it.
- **A caught vocabulary gap** (`src/ui/webapp/shell.tsx`): `commandView` never gained the `/projects` slug when the Projects page landed — the pin (`commandView("/projects") === undefined`) caught it red; the slug is added, so typing `/projects` in the composer now routes like every other page.
- **Filter, exported and pinned** (`src/ui/webapp/app.tsx`): the palette's as-you-type filtering (existing behavior, unchanged) extracted to `filterPaletteCommands` — trimmed, case-insensitive substring on the title; empty/whitespace keeps the full list — exported for the regression pin.
- **The affordance** (`src/ui/webapp/app.tsx`): the status bar's keybind strip carries `<kbd>Ctrl</kbd>+<kbd>K</kbd> palette` beside the existing `Ctrl+P commands` hint. There is no palette button in the shell (the palette is keyboard-opened), so the hint rides the strip the keybinds already live on — no new button.
- **No new deps; no styles.css change** — the new group renders through the existing `palette-group`/`palette-row` classes under the token system.

**Evidence:** red-first — the pins failed verbatim before any src change: `test/webapp-shell.test.ts` → `SyntaxError: The requested module '../src/ui/webapp/app.js' does not provide an export named 'filterPaletteCommands'` (1 fail / 0 pass). The intermediate red also caught the `/projects` gap (above) and one wrong test expectation of my own (the filter pin expected a slash-command id under a query that could not match its title — a test bug, fixed, not a src change). Green: webapp-shell **18/18** (13 pre-existing + 5 new pins: chord, page entries' rail-order dispatch, one-list coexistence, filter, status-bar hint) and webapp-surface **45/45** (the pre-existing palette component pin holds over the widened group union). `npm run lint` exit 0, `npm run typecheck` exit 0 (both unpiped); `node scripts/build-webapp-bundle.mjs` exit 0.

**Honest residual:** Enter-dispatch-closes, Esc-closes, and focus-return-to-invoker are the `CommandPalette` component's pre-existing manners and are unchanged by this slice; the repo has no DOM-event harness, so they stay pinned at the chrome level (`aria-modal`, `palette-backdrop`, the `.palette` selector the global Escape arbitration consults) plus the webapp-surface component pin — not at the event level. The spec's other Option C stretch, the rail-docked palette switcher, remains open.
