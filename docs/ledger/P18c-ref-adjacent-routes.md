### P18(c) - Direct `.git/` ref-adjacent write routes join the W101 protected-target gate (2026-09-30)

**Source:** PARKED_AND_LIMITATIONS.md row P18's part (c) (operator-approved 2026-09-24); SECURITY_ASSURANCE residual #21's still-open part ("ref-adjacent filesystem routes (direct `.git/` writes) are covered only by the workspace-boundary lanes, not by branch-name targeting"); GitHub issue #296. Dispatched as a subtask of the 2026-09-30 P18 wave, branch `feat/p18c-ref-routes` off origin/main.

**What landed.** A direct `.git/` ref write now classifies through the SAME W101 protected-target gate that classifies the command spellings, instead of only the outer workspace-boundary lanes:

- **The classifier** `directRefWriteTargetIn` (`mcp-toolbox/apps/workflow-guard-mcp/src/git-policy.ts`) is lexical and spelling-based, reusing the gate's protected set (always-on `{main, master}` ∪ the caller's `protectedBranches`), target-classified from any seat. A path carrying a `.git` component whose tail is `refs/heads/<branch>` resolves to that branch name: a protected branch denies `protected-branch-write` with the target named (the intent-identical class of `git update-ref refs/heads/<branch>`), a feature ref keeps the feature-target allow. A ref-adjacent `.git` path with no resolvable branch (`packed-refs`, `HEAD`, `logs`, the `refs` / `refs/heads` directory, the git dir itself) fails closed on parse uncertainty. Lexical `.`/`..` collapse stops a traversal spelling from aliasing a protected ref past the tail match.
- **Two surfaces, one classifier (no duplicated lane).** The shell mutation extractor (`boundary-policy.ts`'s `mutationPaths`) feeds the classifier for shell/git actions — redirects, `tee`, `cp`/`mv`/`ln`, `install`, `rsync`, `cpio`/`scp`, `dd of=`, `truncate`, `sed -i`, `touch`, `rm`, and sh-family `-c` wrappers — placed AFTER the existing guard-tamper / protected-path / workspace-boundary checks so outer containment keeps primacy. The `file_write` lane's path loop (`policy.ts`) applies the same classifier path-for-path, including patch targets. `boundary-policy` imports the classifier from `git-policy` (the gate file); `git-policy` does not import the boundary lane, so there is no import cycle.
- **Docs.** A dated 2026-09-30 entry in `mcp-toolbox/apps/workflow-guard-mcp/docs/policy-coverage.md` (the W088/W089/W108 style), the P18 row's dated landed note in `docs/PARKED_AND_LIMITATIONS.md` (append-only), and a dated disposition note on SECURITY_ASSURANCE residual #21 (the entry keeps its number).
