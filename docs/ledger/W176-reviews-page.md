**What landed:**

- **The Reviews page** (`src/ui/webapp/reviews-view.tsx`, new): one row per review-gated run, the row set derived ONLY from the `/api/runs` relay's records (the same `RunsRecordState` mirror + poll the Runs page uses — no new relay): a run is review-gated when `reviewOutcomes` or `blockingReasons` carry its run id, or its registry row's recorded state is `VERIFYING` (the operator-posture projection's own gating rule, `operator-posture.ts:133`); the union renders in record order — registry rows first, then gate-map ids no registry row carries (bounded journals outlive the live projection; those runs render without a state or time rather than being dropped).
- **Verdict from the record's own vocabulary:** `reviewVerdictToken` — `approved` says itself; `changes_requested` (the hub reviewer's rejection verdict, which the fail-closed paths record too, `hub-reviewer.ts:82`/`#recordFailClosed:567`) renders `failed`, as do `fail`/`failed`; no outcome record renders `pending` (the verdict has not been recorded — never inferred from the run's state); a verdict outside the recorded vocabulary renders lowercased verbatim, never styled by a guess (the `statusToken` rule). The record itself stays verbatim in the row and the panel.
- **Axes verbatim:** the verdict's axes render the outcome record's summary VERBATIM (CSS line-clamp keeps the row a row; the page never re-parses the summary — source pin). The blocking reason renders verbatim ONLY when the run sits VERIFYING (spec's exact condition); a settled run's lingering blocking record renders nothing in the row (the detail panel's Review tab carries the record) and a VERIFYING run without one names the absence.
- **Columns:** run id (mono) · origin (`formatRunOrigin`, the origins record — "origin not recorded" otherwise) · verdict (approved/failed/pending, token-colored) · axes named by the verdict ("no verdict axes recorded yet" without an outcome) · blocking reason · recorded time (the row's own `startedAt` where the record carries one, "no recorded time" otherwise; no duration ever derived).
- **Verdict filter** (the cheap one; the spec names no filter for this page): one select whose options derive from the derived rows (all + the buckets actually produced, first-seen order) — the page never offers a bucket no record made; a matching-nothing filter names itself ("no review-gated runs match the filter").
- **Named absences:** unanswered poll ("state unavailable — the runs relay has not answered"), relay null with the transport's reason ("runs relay unavailable (…)"), empty page names the first action ("no review-gated runs recorded — a run reaches this page when its task sits VERIFYING or the reviewer records a verdict").
- **Shared detail panel on the Review tab:** `RunDetailPanel` gains an `initialTab?: RunDetailTab` prop (initializer only; the strip stays operator-owned after the first render; the default stays Summary, so the Runs page behavior is untouched); the tab vocabulary moved to `run-detail-state.ts` as `RUN_DETAIL_TABS`/`RunDetailTab` — ONE list the panel's strip renders and the persisted opener record validates against; `RunDetailOpen` gains `tab?`, validated on read (unknown/wrong-typed tab drops the record, nothing coerced). `app.tsx`'s `openRunDetail(runId, opener, tab?)` now carries the opener page and target tab; the reviews page calls `openRunDetail(runId, "reviews", "review")` and its panel mounts with `key={runId}` and `initialTab={runDetail.tab ?? "review"}` — every row click opens the shared panel on its Review tab, the back affordance returns to Reviews (the origin memory), and Esc/back focus the invoking row (rows carry `data-run-row`).
- **Placeholder retirement:** the last `PhasePlaceholder` use (reviews) is replaced by the page — the component and its styles are deleted from `app.tsx`/`styles.css`; no phase placeholder remains anywhere in the app.
- **Styles** (`src/ui/webapp/styles.css`): `.reviews-*` additions in the token system — the rows reuse the runs-row chrome (`runs-row`/`runs-head` classes) with the grid re-cut to the review row's six columns (`.reviews-head`/`.reviews-row` override), verdict classes `runs-verdict-{approved,failed,pending}`, clamped axes cell, failing-color blocking cell; the reviews page reuses the one dock region (`.runs-detail`).
