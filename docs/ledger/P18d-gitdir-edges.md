### P18(d) - The inspectable env-spelled gitdir route joins the P18(c) direct-write gate (2026-09-30)

**Source:** PARKED_AND_LIMITATIONS.md row P18's recorded boundary from the P18(c) entry ("a gitdir NOT named `.git` (a bare repo or a `GIT_DIR`-spelled directory)", "a case-variant `.GIT/` path"); SECURITY_ASSURANCE residual #21's RESOLVED PART 2 boundary; GitHub issue #296. Dispatched as a subtask of the 2026-09-30 P18 wave, branch `feat/p18-gitdir-edges` off origin/main.

**What landed.** The P18(c) classifier required a literal `.git` path component, so a bare repo or a `GIT_DIR`-spelled directory — whose ref-adjacent writes carry no `.git` — was invisible to the branch-target gate. Two inspectable extensions, one classifier:

- **The env-spelled gitdir route.** `gitDirSpellingsIn(command)` (`git-policy.ts`) extracts the gitdir spellings a command names through its environment in command position — `GIT_DIR=…`, `GIT_COMMON_DIR=…`, `GIT_WORK_TREE=…` — including after `env`/`export` options and across `;`/`&&` segments (`export GIT_DIR=…; echo …`), so argument data (`echo GIT_DIR=/x`) is not mistaken for a live assignment. `directRefWriteTargetIn(path, { gitDirs })` then treats a write under one of those directories as ref-adjacent and classifies its tail with the SAME shared logic (`refTailTarget`): a `refs/heads/<branch>` tail resolves to the branch name (protected denies with the target named, feature ref keeps the allow), a ref-adjacent tail with no resolvable branch (`packed-refs`, `HEAD`, `logs`, the `refs`/`refs/heads` directory, the gitdir itself) fails closed, and non-ref content (`index`, `objects`, `config`, `refs/tags`) stays outside the branch-target gate.
- **The `.git` component match is now case-insensitive**, so the case-variant `.GIT/` path (the same directory on a case-insensitive filesystem) classifies identically. The branch tail stays case-sensitive (git branch names are); lexical `.`/`..` collapse is preserved with the leading `/` kept so an absolute path and a relative spelling cannot collide.
- **Two surfaces, one classifier (unchanged wiring).** The shell mutation extractor (`boundary-policy.ts`'s `checkBoundaryPolicy`) computes the command's gitdir spellings once and passes them to every target; `boundary-policy` imports `gitDirSpellingsIn` from the gate file (no import cycle). The `file_write` lane (`policy.ts`) has no command, so it keeps the `.git`-component route only (the env spelling is not available on that surface).

**Boundaries (remain, recorded honestly):** a `.git` symlink hop whose write spelling carries no `.git` component (resolving the symlink is a filesystem fact the lexical classifier does not read — a `.git` component that IS spelled classifies as before, and the env route above is the inspectable substitute when the gitdir is named explicitly); a gitfile working directory (`.git` is a file naming its gitdir — `.git` itself fails closed, the named gitdir is reachable only when also env-spelled); an unresolved or globbed gitdir spelling (`GIT_DIR=$X`, `GIT_DIR=*` — dropped, since it cannot be matched; an unresolved PATH under a literal gitdir fails closed); and non-ref `.git` content (objects, index, config, hooks, refs/tags — a different policy surface: `.git/config` would need an alias/hooks rule, not branch-name targeting).
