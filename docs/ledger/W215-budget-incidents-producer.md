### W215 - The `budgetIncidents` producer: the WebSessionManager-derived records compose into `GET /api/posture` (2026-10-17)

**Source:** the AgentsView budget-incident panel (`src/ui/webapp/agents-view.tsx:223-249`, `BudgetIncidentRows`) rendered the named absence in production forever: the W176 seam `budgetIncidents?: () => readonly PostureBudgetIncident[] | undefined` was DECLARED on both `HubRequestContext` and `HubBridgeCapabilities` (`src/integrations/hub-http.ts`) and CONSUMED in the `/snapshot` handler, but produced NOWHERE — `src/cli/hub.ts` and `src/integrations/workflow-hub.ts` never named it, and it was absent from `createWorkflowHub`'s options type and from the `createWorkflowHubBridge(...)` forward list. The same declared-but-never-forwarded defect class as the W212 P0 (the W213 ledger's cite).

**Process-topology finding (the crux).** The hub process (`createWorkflowHub` → `createWorkflowHubBridge`) composes NO interactive session manager — `startHubWebUi` (`src/cli/web-service.ts:38-56`) mounts the operator UI over the bridge and nothing else; the hub's only budget guards belong to its scheduled/RSI/reviewer RUNS (`src/cli/hub.ts:763-772` detects `budgetGuard.violation()` and fails the run with it — recorded blocking state already, never a session incident). The web process (`createWorkflowWebServer`) owns the interactive registry (`WebSessionManager`); each `list()` meta carries the recorded `SessionBudgetPosture` — the `sessionBudgetTier`-derived tier (with the guard's own predicates), the recorded mechanism, and the recorded sticky refusal when live (`src/ui/web-sessions.ts:750-778`). The panel's records ARE the interactive sessions' budget state; only the web process can see them.

**Decision.** The WEB process is the producer:

- `sessionBudgetIncidents(sessions)` (`src/ui/web-sessions.ts`) derives one `PostureBudgetIncident` per session whose RECORDED tier is `warn` or `abort` — `under`, `unknown`, and the no-local-cap state emit NO row. `sessionId`/`title`/recorded `mechanism` ride verbatim; `reason` is the recorded sticky refusal when one exists (a warn crossing has none — never invented).
- `withSessionBudgetIncidents(posture, sessions)` (same file) merges the records into the hub-computed posture at `GET /api/posture` (`src/ui/web.ts` `hubPosture`). The honest-degradation contract holds end to end: no registry (a single-session server) → the hub's answer passes through untouched; no tier crossed → the block passes through untouched so the panel renders the NAMED ABSENCE from the absent field — never a fabricated `[]` (an empty record set would claim a successfully-read empty incident source); records present → they ride verbatim, the count recomposes to the record count, and the "per-session budget state" degradation lifts, exactly the projection's own composition rule, so the served wire cannot contradict itself. The input block is never mutated.
- **The hub-side declared-only gap is resolved by REMOVAL, not forwarding.** Rationale: (a) the hub has no session registry by design, so nothing honest stands behind a forwarder; (b) grafting run ids onto the session-shaped record (action target `#session:<id>`) would fabricate session semantics the record contract does not carry — hub-run budget trips are already honest as FAILED runs and recorded blocking reasons; (c) the web-side merge never flows through the hub, so a hub seam it cannot feed is permanently dead. The field, its capability twin, the `/snapshot` consumer, and the now-dead import are deleted (`src/integrations/hub-http.ts`); the hub posture keeps the projection's honest degradation (null count, the registry named in `degraded`, no rows) — pinned hub-side by `test/hub-composition-forwarding.test.ts` (W215 case).

**Production-path pin (the W212 P0 lesson).** The relay pins drive REAL composition — a real `createWorkflowHub` (published discovery file), a real `WebSessionManager` over a seeded registry with env caps, and the real `createWorkflowWebServer` route — never a hand-built posture/context.
