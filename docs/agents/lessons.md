## LESS-0002 — idempotent child teardown closes the double-delivery abort (iteration 2, ACCEPTED)

- lesson: when a parent forwards lifecycle signals to children, exit codes stay 0 whether the child shut down cleanly or was default-killed mid-cleanup — the only discriminating observable is a cleanup side effect (here: discovery.json unlinked by hub.close()), so pin cleanup completion, not exit codes; child shutdown must be idempotent (guarded `process.on`, not `process.once`) whenever a group signal and a forward can both arrive; residual P2 to follow up: SIGHUP still orphans the tui's detached opencode client (neither launcher nor attach handles it; hub side self-heals), and a hung hub.close() is now uninterruptible by SIGTERM/SIGINT (SIGKILL only).
