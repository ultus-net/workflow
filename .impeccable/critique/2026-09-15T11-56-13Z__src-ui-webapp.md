## Design Specificity Verdict

**LLM assessment:** The foundation is authored, not slop: the amber-on-near-black part grammar (2px border-left cards encoding the propose→authorize→act→verify loop), monospace-everything register, uppercase micro-labels, and strict disclosure discipline are product-specific. The slop is concentrated in the newest affordances: 999px pill pickers next to 8-10px cards, hover-reveal Copy/Edit, star favourites chrome on every option row, an amber user bubble that outranks everything including permission prompts, and an 11-step type scale where the design system implies few.

**Deterministic scan:** CLI detector: 1 finding (side-tab on `.aui-md blockquote` — false positive, markdown blockquote convention). Browser detector (19 findings): 13× line-length (chat-column geometry, judgment-dependent), 3× text-occlusion (all false positives: popover-over-content, transient geometry, scroll-clipping), 1× thin-border-wide-shadow (standard popover idiom), 2× undersized-ui-text (TRUE: 10.88px group headers), 1× flat-type-hierarchy (TRUE: 10-11 sizes in a 1.4:1 band — converges with the review's token-drift finding).

## What's Working

1. **The part grammar** — border-left color coding with uppercase micro-labels makes the authorization loop legible at a glance; it is the product's design signature.
2. **Progressive disclosure discipline** — thinking, tool I/O, failure detail, settings, combobox search all collapsed by default; "Forget N remembered decisions" is excellent copy.
3. **Truthful state rendering** — non-advertised current values shown anyway, disabled toggles explain why, describeFailure translates kernel-speak to plain language.

## Priority Issues

1. **[P0] Permission prompt has less visual authority than a chat bubble.** In-flow alertdialog, no focus management, no scroll guarantee, four adjacent equal-weight buttons, "Always" without scope, up to 1s poll latency — at the exact moment the product exercises its reason to exist. Fix: raised surface + accent header, focus Allow on appearance, scrollIntoView + polite announcement, group as Allow once | Always (this tool) vs Deny once | Always deny, show remembered count inline. → `$impeccable polish` + `$impeccable harden`
2. **[P1] Advisory/enforced equivalence violates a core product invariant.** PRODUCT.md: advisory "must never appear equivalent to enforced" — both render as the same muted span, differentiated by one word. Fix: persistent amber-outlined badge for advisory, neutral filled for enforced; echo at the composer. → `$impeccable clarify`
3. **[P1] Escape-to-close-chrome cancels a running turn.** The combobox pop is `.config-combobox-pop`, not covered by the Esc guards; Esc while the picker is open (focus on trigger/stars) cancels the turn AND closes the picker. Fix: stopPropagation in close handlers + guard on any open popover/combobox. → `$impeccable harden`
4. **[P1] Focus trail fails on primary controls.** `.btn-send` has zero visible focus (border already accent), keyboard-active combobox row is 1.10:1 contrast, settings dialog opens with focus on BODY. Fix: distinct focus ring, accent-tinted active row, focus first control on open. → `$impeccable audit` + `$impeccable polish`
5. **[P2] Token drift inside a tokenized system.** One `--radius:10px` declared, eight values in use; 11 font sizes; a third part-card recipe (permission/attention); 10.88px group headers. This is the mechanical form of the "slop leaking" complaint. Fix: commit to 2-3 radii, 4-step type scale, one part-card recipe. → `$impeccable distill` + `$impeccable typeset`

## Persona Red Flags

- **Alex (power user):** Esc-while-picker-open cancels the running turn; shortcuts exist but are advertised nowhere; Regenerate is mouse-only.
- **Sam (keyboard/screen reader):** alertdialog/dialog with focus left on BODY; invisible active combobox option (1.10:1); every config explanation trapped in title tooltips; hover-only Copy/Edit buttons.
- **Jordan (first-timer):** status line reads "ADVISORY / acp" with no explanation; repeated command denials in the thread with no pointer to the Shell toggle that fixes it; "checkpoint" means nothing to a newcomer.

## Minor Observations

- Mobile hierarchy inversion: config dock (295px) outweighs the transcript viewport (253px); touch targets below 44px (copy 45×17, gear 45×30).
- `.config-permissions` class reused for the Notifications section.
- Queue indicator and Export/usage row have mixed alignments; queue never shows the queued text.
- `--fail` red is the palette's weakest color (4.17:1) and carries the most important labels at 0.72rem.
- Success ("completed") is dimmed to 0.75 while failure is the best-designed moment — peak-end inverted.

## Questions to Consider

1. If the permission prompt is the reason this product exists, why does it have less visual authority than the user's chat bubble?
2. Can "advisory must never appear equivalent to enforced" be honored by a single muted word?
3. Do operators switch models often enough to justify 150px of pickers beside the composer, or would one status chip + gear buy back the conversation?
